For every future change

  1. Identify the owner Sheet and its exact tab, permanent row ID and permission controls; do a fresh authorized read.
  2. Record the decision, affected code/data output, source revision or row date and the remaining unknowns in the versioned ledger.
  3. Change only the authorized source or Git code; do not create another editable master.
  4. Validate public data and the mobile/desktop interactions using safe fixtures, then verify real Google Sheets production publication.
  5. Record PR/commit, successful Actions run, served website readback and any open holds before calling the work released.

Important: `Completed` in a project register is a listed lifecycle status, not independent proof of engineer-certified completion. A hidden status cannot be derived from work reports. Materials, equipment and manpower-shortage maps still lack authorized live demand feeds.

Current limitations and corrections

The Website Publishing and Source Directory is a joined navigation workbook; only its source-directory tab participates in publisher pointer checks, not the joined private tables. Source dates and publisher timestamps have different meanings. Revisions, deleted rows and corrected reports must be handled by the owning source and documented.
