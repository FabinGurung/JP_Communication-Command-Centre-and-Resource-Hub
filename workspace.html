Neon / PostgreSQL status in this repository

Current truth: this website does not require a live Neon database. The file ops/schema/daily-ops-postgres.sql is currently a PostgreSQL-compatible schema contract: it defines tables, keys, foreign keys and constraints so humans and AI agree on the relationships. The live Pages site reads CSV/JSON/JSONL directly.

If a Neon project was created separately, this branch is not depending on it: there is no database connection string, database client or backend request in the current Pages runtime. Neon only becomes useful when we need secure authenticated writes, many simultaneous users, server-side queries, transactions, row-level access, or a real app/API rather than a static site.

Project name / location / status
Edit projects.csv.
Today's work / blocker / readiness

Attach a drawing or report
Keep the file in Drive; add/update its normalized relationship in ops/data/project-resources.json.
Change website labels / map statuses
Edit map-config.json.
Change data relationships
Edit the schema contract only when the data model genuinely changes: ops/schema/daily-ops-postgres.sql.
Check if website update passed
Open GitHub Actions, verify the latest run is green, then inspect the public page.

What this Workspace is — and is not

Important: this is a public GitHub Pages site. It is safe as a guide and read-only control desk, but it should not contain GitHub tokens, Drive credentials, database passwords or private client data. A true write-back admin portal would require authentication plus a backend/API.
