<main id="main" class="wrap"><div class="section-head"><div><h2>Seven complementary formats</h2><p class="hint">One source of evidence; multiple reproducible ways to query it. None of the derived formats should silently become a new authority.</p></div></div>
<div id="formats" class="cards" aria-live="polite">
<article class="card"><div class="index">01 / EVENT EXCHANGE</div><h3>JSONL / NDJSON</h3><p>One UTF-8 event per line with provider IDs and revisions.</p></article>
<article class="card"><div class="index">02 / ORIGINAL FILES</div><h3>Original bytes + SHA-256</h3><p>Photos, PDF, DWG, SKP, E2K and attachments retained in Drive.</p></article>
<article class="card"><div class="index">03 / PROVENANCE</div><h3>JSON manifests</h3><p>Cursors, checksums, IDs, source links and PRE/POST/ACK receipts.</p></article>
<article class="card"><div class="index">04 / ANALYTICS</div><h3>Parquet</h3><p>Optional columnar query projection.</p></article>
<article class="card"><div class="index">05 / SEARCH</div><h3>SQLite / DuckDB</h3><p>Rebuildable indexes and joins.</p></article>
<article class="card"><div class="index">06 / HISTORY</div><h3>Compressed partitions</h3><p>Reversible archival ranges with hashes and manifests.</p></article>
<article class="card"><div class="index">07 / CONTRACT</div><h3>JSON Schema / SQL DDL</h3><p>Stable validation, identity and relationship rules.</p></article></div>
<section class="panel"><h2>The evidence journey</h2><div class="steps"><div class="step"><b>1. Capture</b>Slack, Discord, field files and future authorized providers</div><div class="step"><b>2. Preserve</b>Original bytes, messages, thread IDs, revisions and hash metadata in private Drive</div><div class="step"><b>3. Normalize</b>Deterministic event IDs, project FK and admission/uncertainty states</div><div class="step"><b>4. Query</b>Rebuildable JSONL, SQL, Parquet or DuckDB views</div><div class="step"><b>5. Present</b>Approved, public-safe website information and Drive-gated resource links</div></div>
<div class="status"><article><b>Discord · partial</b><span>Raw JSONL/receipts exist; 749 original-media fidelity mismatches and archived-thread gaps remain open.</span></article><article><b>Slack · partial</b><span>Queryable provider registers exist; full historical private raw archive and cursor coverage are not certified.</span></article><article><b>Parquet / DuckDB</b><span>Optional future projections; no production implementation is claimed here.</span></article></div>
<div class="notice"><b>Never conflate proof states.</b> Uploaded ≠ verified · Stock ≠ used · Ordered ≠ delivered · Plan ≠ done · Derivative image ≠ byte-identical original. Unverified source data remains explicitly uncertain.</div></section>
<section class="panel"><h2>Protection and lineage rules</h2><ol id="rules" class="rules"><li>Preserve original source bytes in Drive with permission-gated access.</li><li>Do not publish raw provider messages or protected source files in a public GitHub repository.</li><li>Retain the source provider ID, timestamps and correction history.</li><li>Never treat a derived index as original evidence.</li><li>Log missing threads, attachments and unverified byte identity explicitly.</li><li>Save PRE/POST/ACK and provider-readback receipts for governed changes.</li></ol>
