## Unresolved and blocked items
1. `INCOMPLETE`: current field data dates from October. Newer field work must be acquired in its owning source, source-dated and reviewed before adding it to the same-ID register. A site publisher refresh alone cannot fabricate newer facts.
2. `BLOCKED`: no production Slack/Discord/Telegram collector, provider cursor, replay/tombstone machinery or approved direct-to-Sheets importer in the current Actions job. Public Slack search in this session surfaced only a generic welcome notice, not a supported project work instruction. Do not claim live conversation coverage.
3. `INCOMPLETE`: verify bytes and version from one existing saved message original in its restricted Drive folder; reconcile recorded SHA-256 without publishing the original content. Preserve occurrence-vs-content-hash distinction.
4. `UNRESOLVED`: reviewed notification != outstanding task; `UNVERIFIED` work != certified completion. Do not label overdue or complete based on missing updates.
5. `INCOMPLETE`: phone usability checks must prove the header and navigation fit 320–430 CSS px without browser auto-zoom or clipped technical strings. Automated Chromium QA is not a physical iOS Safari QA claim.

## Next bounded batch (Run 02)
- **Intake:** pick **one actually available project-specific Slack channel or one stored Drive message folder**, record source conversation ID / cursor / message IDs, and compare its recent original records with `message_sources`; do not scan all providers at once. Discord/Telegram each stay a separate held lane until authorized integrations and source channels are grounded.

- **Review:** propose at most **three** newly corroborated instruction rows, matched by source ID, date, category, project ID, review status and publish approval, without guessing resolved state or owner.
