# v3.2.0 — Source-reviewed Closed & Archived Work

**Date:** 14 November 2026 (NPT). **Owner:** JP Site Operations (Operations source registration and public interface only).

## User outcome
Add a **separate, secondary, mobile-usable** `/closed-work.html` to hold approved historical outcomes: **Completed**, **No longer required**, **Cancelled**, and **Superseded**. It is reachable through Site updates, not an extra main header tab, and cannot clutter the map or Notification Center.

An approved closure removes only the specific public notice/work item from the ACTIVE notification/work projection. **The public project and approved map pin remain.** Historical stable IDs and reviewed work text are preserved in `closed-work.json` and the original Google Sheets. A closed item is never physically deleted from its source.

Therefore the first real Closed & Archived Work page correctly shows **zero** confirmed closed items.

## Closure contract (same original live IDs, no second master)

The following optional columns are to be added to the **same two original tabs** after A7 PRE snapshot, approved source schema edit, readback, POST snapshot and audit log; the publisher already safely handles their absence:

| Column | Contract |
| --- | --- |
| `Closure Decision` | Blank/OPEN/ACTIVE/REOPENED (active), or `COMPLETED`, `NOT_REQUIRED`, `CANCELLED`, `SUPERSEDED` |
| `Closure Approved` | Only explicit `TRUE` promotes to archived; otherwise remain active |
| `Closure Date` | ISO `YYYY-MM-DD`, source-reviewed effective date |
| `Closure Reviewer` | Source-held reviewer identity; **never** exposed publicly |
| `Closure Reason` | Source-held rationale; **never** exposed publicly (may contain private facts) |
| `Closure Evidence` | Required for COMPLETED, kept in restricted source/Drive |
| `Superseded By` | Required if decision is SUPERSEDED; stable replacement reference |

For a **Project Work** completion, `Verification Status = VERIFIED` is additionally mandatory; recorded work percentages, activity descriptions, old Due Dates, and the **project-level Completed status** do not by themselves close anything. A notification completion is an approved administrative decision, not automatically a signed engineering completion certificate.

If an approved closure is incomplete or unknown, publication **fails closed**, exposing no ambiguous historical state. If it is submitted but not approved, the item stays active. An actual reopen/changed decision requires an append-only audit event with original ID, prior state, actor, effective time and evidence in the owning governance records; editing fields alone must not erase earlier receipt.

## Publication model

```
7 original Sheets (read-only, double-read, source permission controls)
        │
        ├─ approved public projects ─► Project Map (same pins)
        ├─ reviewed items with NO approved closure ─► Notifications / Site updates
        └─ explicit approved closures ─► closed-work.json ─► Closed & Archived Work page
```

`closed-work.json` contains only the public stable item ID, approved project name/ID, previously public work/notice summary, status category, source date and closure date. It never embeds reviewer, reason, private evidence, financial amounts, worker identities or private projects.
