# v2.4.0 — Project Maps and Progress Dashboard

**Scope:** A9 Operations/Communication repository only. **Authority:** original five live Google Sheets, original Slack/Discord messages and their archives, and public-safe GitHub source projections. This release does not rename the repository or change the other A9 repositories.

## Delivered software
- A slim, responsive north/west/centre/east/south dashboard in the primary Sheets-published Pages artifact.
- Map and approved project index, organization and reporting-date filters, per-project context, source-reviewed notices, dated reported-work cards, and reporting-activity trends.
- Public-safe organization display names resolved from the repository's existing explicitly public organization index; unknown or nonpublic organizations do not obtain a name in the projection.
- Provenance block distinguishing **publication readback time** from the **latest public work-report date**. Explicit markers that direct Slack ingestion is not in this publisher and that the Discord collector remains on hold.
- Additional publication regression checks: records from private projects and private costs do not leak; field-reported status is not presented as engineer-certified completion.

## Governance
The five source workbooks remain under their original Google IDs: Projects and Locations; Website Display Choices; Notification Center — Message Sources; Notification Center — Instructions; Project Work. Approved public project, instruction, and work-row filters are enforced during build. No direct source sheet IDs or raw messages are embedded in operations.json. Original project IDs and legacy project query aliases are preserved.

This is not a labour/payroll database, a certified construction measurement, a shadow schedule, or a commercial cost engine. Project Work verification labels reproduce the owning Sheet state only. No unverified report is converted into an engineering acceptance or billable quantity.

The earlier 37 historical public progress observations remain in their frozen archive. Direct Discord capture was previously put **ON HOLD**; this release does not reactivate it. Slack reads from the conversational connector are not a production ingestion service and do not establish full channel coverage.

## Release criteria
1. Validate Node.js syntax and Python publication tests on the PR and on the production commit.
2. Read all five Sheets through the already-authorized main Workload Identity path and generate a read-only public snapshot.
3. Publish the artifact to GitHub Pages. Do not release if project/source readback or deployment fails.
4. Compare the live HTML, CSS and JavaScript to the release commit, inspect published provenance, then create the v2.4.0 GitHub release on that exact commit.
5. Preserve legacy resource, Astam, Workspace, Guide and project routes.

## Remaining scope
- Authenticated Discord replay, media-fidelity reconciliation and source deletion/tombstone acknowledgements require explicit approval and provider-specific evidence.
- Direct Slack-to-dashboard collector with per-channel cursors and consent-controlled private coverage is not yet deployed.
- Human acceptance of reported work, revision history and certified quantities must remain with owning providers, not with a browser metric.
- Production browser QA needs desktop/tablet/mobile interactive inspection beyond the source and CI checks.
- Historical archived repository content and A7 identity routes are retained pending separate governed reconciliation.
