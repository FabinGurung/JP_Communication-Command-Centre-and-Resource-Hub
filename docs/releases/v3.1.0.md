# v3.1.0 — Site updates without dashboard clutter

**Date:** 14 November 2026 (NPT). **Scope:** JP Site Operations only. Based on user field-device QA.

## What changed
- The former seven-link, full-screen iPhone Menu is removed. A small, always-visible, touch-friendly three-tab header provides **Map · Notifications · Site updates** on desktop and phone; no overlay menu, and no horizontal header scroll required. Secondary and historical routes remain through footer/expanded source links.
- The mistaken four-column extraction template has been replaced **at the same original URL** `/extraction.html` with a useful, readable **Site updates** view. The Run 51 principle (source occurrence → version/evidence → review → publish/checkpoint) remains **inside the publisher and governance notes**, not as visible field-user workstreams.
- Updated `scripts/publish_operations.py` derives `site-updates.json` from the **same seven original, read-only, double-read Google Sheets** that produce `operations.json`. Per-site approved public counts, latest recorded dates, reviewed Work/Materials/Supervision categories, and unverified work counts are source-keyed; original message and financial data remain private.
- Human-facing interpretations identify what can and cannot be concluded: reviewed notification != unresolved instruction; work report != certified completion; missing source rows != inactivity. Site update cards reveal reviewed original instruction text and report descriptions from the already approved `operations.json`.
- Clicking Site updates from the notification desk retains the selected project ID. Older `progress.html`, `sources.html`, `owner-help.html`, `memory-wall.html`, Resource Library and Astam redirect routes are preserved but no longer main phone navigation items.

## Simplified GitHub Actions
The active `Operations from Google Sheets` workflow retains four essential execution stages: unit/privacy tests, Chromium/WebKit QA on code changes, authenticated Google Sheets projection, and Pages deploy. **Eight obsolete version-specific release jobs** are removed from the current workflow; their already-issued Git tags, GitHub releases, historical Actions receipts, and rollback commits remain untouched. New release `v3.1.0` uses a single post-deploy verifier of the exact serving JS/HTML/CSS, approved `operations.json`, new `site-updates.json`, and existing Library/Astam redirects. Hourly source runs do not run the browser QA or release check.

## Acceptance
- Mobile 390px and 320px Chromium and mobile-WebKit smoke tests: three 44px+ direct taps; source/notification filters; per-site updates; no horizontal overflow, overlays, or iOS auto-zoom on form fields.
- Unit privacy/source-projection tests: `site-updates.json` excludes private projects, status withheld by Show Status, and retired aliases; counts reconcile exactly with public `operations.json` and no false completeness.
- Authenticated seven original Sheet double-read; Pages post-deploy byte parity; original project/review/work counts consistent; exact-commit `v3.1.0` release gate.
- No assertion of real-time Slack/Discord/WhatsApp collector. Source-specific ingestion, revisions and tombstones remain follow-up tasks under Operations [issue #30](https://github.com/FabinGurung/jp-site-operations/issues/30).

**Do not delete existing released artifacts to simplify a user's navigation.** The former v3.0.0 release is the PRE milestone, retained in GitHub and available for rollback.
