# Operations v2.7.0 — Mobile Source-Status Filter & Decision Memory Wall

**Decision date:** 12 November 2026 (Asia/Kathmandu).

## User-facing change
- Mobile (up to 760px): a single, keyboard-operable, horizontally scrollable set of touch targets (at least 44px high): All, Construction, Completed, Approval, Maintenance, Not stated. This avoids adding a second large button grid to the site map.
- Desktop: one compact dropdown with the same categories and counts, integrated in the existing Project Navigator.
- Both filter the same approved public sites on the map, source-backed project directory, work reports and reviewed instructions. Counts are derived at runtime from the **currently published** `operations.json` result; no live project counts are hardcoded in the JavaScript.
- Choosing a direct project resets the status category so the UI cannot silently combine incompatible selections. Clearing filters restores All. Existing company/date/map-layer choices remain as before.
- `Completed` is the **listed project status** in the source register, not a signed construction-completion or work-inspection acceptance.

## Versioned memory and source audit
- [Owner-facing Memory Wall](https://fabingurung.github.io/jp-site-operations/memory-wall.html) is published alongside the dashboard and linked from the dashboard and owner-help page.
- `docs/operations/OPERATIONS_SOURCE_DECISIONS_MEMORY_WALL.md` holds decisions, exact source IDs/tabs/fields, status-policy/limitations, revised files and future update checklist.
- `ops/control/operations-source-decision-ledger.v1.json` mirrors machine-readable routes and dated decisions, not private or editable factual data.
- `AGENTS.md` pins the rule that future Operations facts must derive from actual owning Google Sheets; code/UX implementation is versioned Git logic, not data fetched from Sheets.

## QA and release acceptance
- Python privacy and publication tests prove `Show Status = FALSE` stays hidden even when a public project is displayed, and private rows do not reach `operations.json`.
- Synthetic Playwright Chromium at mobile viewport 390x844 and desktop 1280x800 checks all categories, approved map-marker counts, matching project lists, select/button synchronization, touch target size, keyboard access, reset, direct project selection, no page overflow and the published memory-wall route.
- Actual production release requires the double-read from the original five Google Sheets, successful Pages deploy, served HTML/CSS/JS/help/memory-wall parity and public snapshot schema/provenance check; do not tag until the live gate passes.

## Open holds / unchanged boundaries
Source project status is not an engineer's quantity or work completion certificate. The work task register, source corrections/supersessions, material/equipment requisitions and crew-demand availability are separate governed workstreams under [issue #30](https://github.com/FabinGurung/jp-site-operations/issues/30) and [issue #34](https://github.com/FabinGurung/jp-site-operations/issues/34). No original Google Sheet content or Drive permissions changed in this release.
